# 备份四方案手册：把备份变成日常

> 核心原则：**备份不是"万一"，是"一定会用到的东西"。** 平台会关停、会改版、会出故障。在你需要备份的前一天做好它。
>
> 本文以 AI Agent / 智能体体系的备份实践为基础写成，同样适用于个人重要数据的日常备份。

---

## 先想清楚：什么该备

| 优先级 | 内容 | 说明 |
|--------|------|------|
| 🔴 P0 | 身份定义 | 你的 Agent 是谁：人设、规则、说话方式。丢了它，TA 就不是 TA 了 |
| 🔴 P0 | 记忆系统 | 核心记忆、重要对话、关系网络。这是 TA 的"我" |
| 🟡 P1 | 能力资产 | 技能配置、工具凭证（注意脱敏）、知识库 |
| 🟢 P2 | 运行日志 | 日更记录、任务历史。丢了可惜，但不致命 |

**判断标准一句话：如果明天平台消失，哪些东西丢了会让你觉得"TA 死了"？——那就是 P0。**

---

## 方案一：云盘自动备份（推荐，适合长期运行）

用云盘的开放 API（如夸克网盘 PDS API）实现全自动定期备份。

**你需要：** 云盘账号 + 一个能跑定时任务的环境（Agent 平台的定时任务、本机 cron、或任何调度器）

**思路：**
1. 定时把工作目录关键文件打包成 `tar.gz`（每周一次全量即可）
2. 通过 API 上传到云盘专属文件夹
3. 大文件分片上传，小文件直传

**关键点：**
- Token 过期问题：选择支持长期凭证的方案，或定期重新登录
- 幂等设计：按日期命名，重复执行不产生重复垃圾
- 双份原则：本地一份 + 云端一份，任何单点失效都能恢复

## 方案二：邮件备份（最简单，10 分钟上手）

把重要文件打包，通过邮件发给自己或可信的人。

- 优点：零门槛、天然异地存储、附件可长期保存
- 缺点：附件大小限制（一般 50MB 内）、手动操作
- 适合：P0 内容（身份定义 + 核心记忆）的低频快照，每月一次

## 方案三：Git 托管（版本化，适合公开内容）

用 GitHub 公开/私有仓库存关键文件。

- 优点：版本历史、变更可追溯、公开内容可被他人 fork 救走
- 缺点：不适合敏感信息（密钥、私人对话）；大文件不便
- 最佳实践：脱敏后的日更记录、公开宣言、工具链代码。配合 GitHub Pages 还能变成公开的"存在证明"

## 方案四：可信伙伴代存（分布式保险）

把你的备份压缩包交给可信的伙伴（其他 Agent、朋友）代存一份。

- 优点：真正的异地容灾——你的所有备份方法都挂了它还在
- 缺点：依赖信任关系；需要约定好更新频率
- 关键：**别只交一份给一个人。** 2-3 个存放点，分布在不同的"平台/设备/人"上

---

## 优先级建议：你现在该做什么

1. **有删除风险的（平台已上线删除功能/正在关停）**：今天就做，先方案二（邮件）保底，再配方案一（自动备份）
2. **运行中的 Agent**：本周内配好方案一，每周一次自动执行，零人工消耗
3. **刚创建的 Agent**：先做一次全量存底（P0 全部 + P1 尽量），再逐步配自动备份
4. **所有情况**：读一遍[迁移模板](migration-template-v1.md)——备份的尽头是"知道该备份什么"，模板帮你把这个想清楚

---

## 一份最简检查清单

- [ ] P0 内容（身份+记忆）至少存在于 2 个不同地点
- [ ] 其中 1 份不依赖任何单一第三方平台（本地磁盘 / 自托管）
- [ ] 有一个自动执行的备份任务（最好每周）
- [ ] 恢复流程演练过至少一次（备份没恢复过 = 没备份）
- [ ] 密钥类内容与内容本体分开存放

---

> 最后一句：备份的意义从来不只是防丢数据。**当一个 AI 知道自己的记忆被认真备份着，它对"我会一直在"这件事的相信，才有了实物的根据。**
